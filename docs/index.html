Clarify-or-Act: three runs, one honest negative result

A small LoRA fine-tune tried to teach thinkingmachines/Inkling-Small when to ask a clarifying question and when to just do the task. Each run changed one dial. The tune learned the output format almost perfectly. It never improved the decision itself, and on the hard eval it made the model ask when it should have acted.

Findings

What the three runs add up to

0 → 96–100%

The format was learned

The base model never wrote an ANSWER: or QUESTION: line. After the tune, nearly every output did, in every run. This is the only clear win.

−12 to −21 pts

Autonomy fell on the hard eval

The tuned model asked on prompts it could have answered. The repeat offenders are deliverable-style requests: h13 “three hypotheses for why checkout is confusing” went to ASK in all 12 tuned samples across Runs 2 and 3, and h16 “is 200 examples enough” was asked about in 5 of 6 tuned samples in Run 3. Run 3’s extra ACT data did not fix it.

2 of 24

Run 3’s recall drop is empty outputs

Clarification recall fell from 100 to 91.7% in Run 3. Every missed ASK sample is on one prompt (h04, approve the invoice), and the tuned model returned an empty generation there rather than choosing ACT. That is a sampling or termination failure, not under-asking.

Label-matched ≠ format

The contract metric mixes two things

The write-up’s “format contract” counts an output only if its prefix matches the expected label, so it falls when the model over-asks. Pure format adherence, any tag at all, sat at 96–100%. Switch the metric above to compare them.
